# meta-thinking-method（元思维分析方法）

一套面向「产出交付物」类任务的迭代式整体重审方法，以 Agent 技能（Skill）形式交付，适用于方案、设计、计划、文档、代码、技能包等一切需要对抗性审查与迭代收敛的产出场景。

## 项目结构

```
meta-thinking-method/
├── README.md                  # 本文件
├── LICENSE                    # MIT 协议
└── meta-thinking-method/
    └── SKILL.md               # 方法本体（技能定义，含 frontmatter）
```

## 这是什么

`SKILL.md` 是一份自包含的方法论文档，定义了一套完整的任务执行契约。当任务被判定为「产出交付物」类时，执行者（人或 AI Agent）从初稿起执行迭代式整体重审，直至收敛判据全部满足；判据未满足的，依契约按未收敛交付、经规则制定者批准的平台收敛或中止收尾。定稿落盘后等待审批。

核心机制概览：

- **迭代式整体重审**：每一轮审查的都是上一轮产出的完整交付物整体，而非单个切面；发现结构性缺陷即修正，产出修订版整体进入下一轮。
- **五判据收敛**：局部性、无结构性变更、再审无新缺陷、破坏性验证通过、备选路线比较完成，五条判据全部满足且满足轮数下限（3 轮，含初稿轮）方告收敛；轮数上限 5 轮，达上限仍未收敛的按未收敛交付处理，经规则制定者批准的平台收敛为另一合法出口。
- **四角色分离**：请求方、执行者、规则制定者、审批人；独立抽核为每批次必做的复核节点，须由未参与当批重审轮的独立主体执行；四角色为同一主体时改由该主体按审批人职能履行，履行记录写入收敛声明。
- **对抗性审查姿态**：每轮从恶意使用者、极限条件、无能实施者、未来维护者四个必选立场（外加每轮必造的自造立场）对产物整体过查，并逐层触及措辞、结构、前提、问题本身四个深度层。
- **五必查维度**：深度层、立场轮换、条款两两互查、防悬空过查、自包含与过程叙述过查，逐轮全量覆盖并留痕。
- **防悬空约束**：示例不等于规格、动态优先、适用面最大化、假设三选一（实测验证／直接消除／动态化吸收）、隐式前提显性化、使用方场景逐一走查、核验覆盖面（依赖的外部对象核验到实施粒度）。
- **五级证据分级**：已实测验证、逻辑推证、静态核验、约定既定、设计保证；结论级别取支撑链中事实类环节的最弱者，约定既定不参与强弱排序，禁止级别洗白。
- **过程与产物分离**：缺陷清单、维度覆盖记录、收敛声明等过程记录随产物另行交付，不写入交付物正文；交付物须自包含、单遍可读。
- **自进化机制**：每次应用后将方法自身缺陷、规则误用或不适用场景以明确选项向规则制定者回流提请，方法修订同样走全套迭代与审批流程。

## 使用方法

本目录是一个标准的 Agent 技能包（技能名 `meta-thinking-method`，入口为 `SKILL.md` 的 frontmatter）。将其放入支持技能机制的 Agent 运行环境（如 Claude Code、DeepSeek Harness 等）的技能目录后，在任务中点名使用「元思维方法」，或在需要对抗性审查、迭代收敛、证据分级、防悬空与自包含约束的交付任务中由 Agent 依其 description 自动匹配调用。

调用本技能后，执行者须先逐行通读 `SKILL.md` 全文，再按契约执行：初稿 → 重审轮迭代（全维度覆盖、立场轮换、互查、信息引入、独立抽核）→ 五判据收敛 → 交付前核实门禁 → 落盘等待审批。
